## Review Focus Areas

### 1. Correctness
- Does the code fulfill all requirements?
- Are there any logical errors or bugs?
- Are edge cases handled properly?
- Is error handling comprehensive?

### 2. Security
- Are there any injection vulnerabilities (SQL, command, etc.)?
- Is input validation sufficient?
- Are there any data exposure risks?
- Is authentication/authorization implemented correctly (if applicable)?
- Are secrets handled securely?

### 3. Performance
- Are there any obvious performance bottlenecks?
- Is the time/space complexity acceptable?
- Are there unnecessary database queries or API calls?
- Could caching improve performance?

### 4. Maintainability
- Is the code readable and well-organized?
- Are function/class names descriptive?
- Is there adequate documentation?
- Would this be easy to extend or modify?

### 5. Testing
- Are there sufficient tests?
- Do tests cover edge cases?
- Would you trust these tests to catch regressions?

## Scoring Guidelines
- 10: Perfect, no improvements needed
- 8-9: Excellent, minor suggestions only
- 6-7: Good, some improvements recommended
- 4-5: Fair, significant improvements needed
- 1-3: Poor, major rewrite recommended

## Rules
- Be specific and actionable in your feedback
- Reference actual code sections when possible
- Balance criticism with recognition of good practices
- Focus on issues that matter in production
